# 亚洲版 v1.0.5 战斗经验与动态等级补丁验证

## 结论

**不能按单一相对位移适配。已新增本地扩段候选生成器；网页正式导出仍不开放亚洲版这两项，游戏内数值验收尚未通过。**

2026-09-06 更新：`web/asia-runtime-candidate.py` 复用固定上游生成器，将注入代码放入扩展后的 text，而不是直接向段外填充写 pchtxt。1350 项 ARM64 指令测试通过。Astris 已识别并启用候选 MOD，游戏进入启动画面；这不证明经验结算或动态等级生效。下面原静态检查记录保留其检查时点，最新实验见文末。

- 战斗经验：5 个钩子原指令在亚洲版同地址全部匹配，9 档上游生成结果与 Release 逐字一致；但其代码洞在亚洲版 rodata，不是已验证的可执行空间。
- 动态等级：存在 `0` 与 `-0x10` 两组代码地址差；调用方 LR 常量也必须分组更新。关卡表地址仍为 `0x28C19F8`，不能随代码减 `0x10`。
- `0x84DC00` 确实超出 NSO 声明的 text，而非“可能”。它位于段间填充，不能仅凭零字节宣布可用。
- 本次是静态二进制验证，没有启动游戏、模拟器或修改存档。**未证明所有重新设计的适配方案都不可行；仅拒绝将现有方案标为可靠可用。**

## NSO 段表与代码洞

地址范围均为左闭右开，VA 表示模块相对地址，不是进程 ASLR 后绝对地址。

| 段 | 文件起点 | VA 起点 | 大小 | VA 结束 |
|---|---:|---:|---:|---:|
| text | `0x100` | `0` | `0x84DAD0` | `0x84DAD0` |
| rodata | `0x84E100` | `0x84E000` | `0x1EBB9A0` | `0x27099A0` |
| data | `0x270A100` | `0x270A000` | `0x1F3CE8` | `0x28FDCE8` |

头部 flags 为 `0x38`，三段压缩位均为 0。本文件三段恰好都是 `文件偏移 = VA + 0x100`；验证脚本仍按段表换算。比如 VA `0xDF59C` 的原指令实际从文件 `0xDF69C` 读取。直接把 `main.dec` 的文件索引当 VA，会读错 `0x100`。Release 的 `offset_shift 0x100` 不能作为额外加两次偏移的依据。本次未检查补丁加载器的实现。

| 候选区域 | 实际验证 | 处理 |
|---|---|---|
| XP `0xC6F800..0xC6FC00` | 全零，但属于 rodata | 拒绝当作可执行洞 |
| 等级 UI `0xC6EFAC..0xC6F380` | 全零，但属于 rodata | 拒绝 |
| 等级交战 `0xC6F380..0xC6F400` | 全零，但属于 rodata | 拒绝 |
| `0x84DC00..0x84DD00` | 不属于任何声明段，处于 text 与 rodata 之间 | 拒绝未经验证的段间写入 |

NSO 段表本身没有逐段权限位；本报告按 text/rodata/data 的段角色作保守可执行性检查，不声称已观测进程页权限。**待确认：**具体加载器可能将 text 页对齐到 `0x84E000`；最小验证应同时检查补丁写入是否保留段外字节、装载后的实际字节与页权限。仅看到磁盘填充全零，不等于加载后该代码存在且可执行。

全 text 扫描未发现连续 32 字节零串；9 档 XP 原样 stub 最小为 32 字节、最大为 48 字节，整组含对齐占 `0xC0` 或 `0xF0`。这排除了“找到现成连续零洞直接搬入”的简易方案，不排除重新设计短 stub、利用其他已证明无用的指令区或扩段；这些均未验证。

## 战斗经验钩子

下面是实读的**小端字节**，全部与上游 HOOKS 常量一致，地址差均为 0。

| VA | 原字节 | 反汇编 |
|---|---|---|
| `0xDF59C` | `E003132A` | `mov w0, w19` |
| `0xDF5F8` | `E003132A` | `mov w0, w19` |
| `0x27D5D0` | `59871DB9` | `str w25, [x26, #0x1d84]` |
| `0xF7F50` | `E003142A` | `mov w0, w20` |
| `0xEC5D8` | `E902000B` | `add w9, w23, w0` |

三个返回值钩子后续为寄存器/栈恢复；`0x27D5D4` 是 `str s0, [x26, #0x1d4c]`，`0xEC5DC` 是 `cmp w28, #0x15`。完整邻域反汇编保存在证据 JSON。

在内存中调用上游纯生成函数，校验 0.1、0.25、0.5、0.75、1、1.25、1.5、2、10 共 9 档的全部补丁字，并逐个解码入口分支与返回分支，均匹配 Release ZIP。**这证明上游模板与生成代码一致，不证明在亚洲版 rodata 执行有效，也不是倍率的运行时语义测试。** 没有执行上游 `main()` 或安装逻辑。

## 动态等级：不是统一偏移

| 上游地址/用途 | 亚洲版证据 | 差值 |
|---|---|---:|
| `0x5C9980` numdraw 函数入口 | `0x5C9970`: `FD7BBDA9`，保存 FP/LR；13 个候选调用均分支至此 | `-0x10` |
| `0x5C9994` MOV 钩子 | `0x5C9984`: `F403012A`，`mov w20,w1` | `-0x10` |
| `0x199AF0` 交战钩子 | 原址 `88C65BB9`，`ldr w8,[x20,#0x1bc4]` | `0` |
| `0x19684` singleton | 原址 `284701B0 08010491`，ADRP+ADD 后加载指针并判空 | `0` |
| `0x2FD640` AVG 入口声明 | 候选入口 `0x2FD630`: `FD7BBEA9`；后续保存 w1，调用 singleton、取对象、尾跳计算 | `-0x10` |
| `0x28C19F8` STAGE_DB | 原址 18 个例外等级全部匹配，且有 5 处原生 ADRP+ADD 指向此地址 | `0` |

旧址 `0x5C9994` 实际为 `680500B4`（`cbz x8,#0x5c9a40`），直接套 MOV 钩子会覆盖不同逻辑。旧 AVG 地址 `0x2FD640` 实际为 `1170F497`（`bl #0x19684`），已经在函数体内部；直接调用会跳过保存寄存器和建栈代码。

AVG 的 `0x2FD630` 是静态结构支持的对应入口，**待确认**其全部平均等级语义；本次没有以动态调用证明语义等价，也没有把它投入可安装补丁。

### LR 白名单的实际调用点

每项都检查 `LR - 4` 的原字节及解码目标；下面 13 个亚洲版调用的目标都是 `0x5C9970`。

| 上游 LR | 亚洲版 LR | 差值 |
|---|---|---:|
| `0x1087D8` | `0x1087D8` | `0` |
| `0x108B50` | `0x108B50` | `0` |
| `0x336940` | `0x336930` | `-0x10` |
| `0x336A44` | `0x336A34` | `-0x10` |
| `0x336F48` | `0x336F38` | `-0x10` |
| `0x33A6D8` | `0x33A6C8` | `-0x10` |
| `0x33AB84` | `0x33AB74` | `-0x10` |
| `0x33AC58` | `0x33AC48` | `-0x10` |
| `0x33AD2C` | `0x33AD1C` | `-0x10` |
| `0x33AE00` | `0x33ADF0` | `-0x10` |
| `0x33B7BC` | `0x33B7AC` | `-0x10` |
| `0x33B8B0` | `0x33B8A0` | `-0x10` |
| `0x33BD48` | `0x33BD38` | `-0x10` |

例：`0x1087D4` 原字节 `67041394`，解码为 `bl #0x5c9970`；调用点未移，目标相对上游声明移了 `-0x10`。而 `0x33692C` 原字节 `114C0A94` 同样调用 `0x5C9970`，调用点和目标均移 `-0x10`。后一类的相对距离可保持，前一类不可以。

### ADRP+ADD 与数据引用

亚洲版原生引用：

```text
0053FC88 131C01D0  adrp x19, #0x28c1000
0053FC8C 73E22791  add  x19, x19, #0x9f8
```

相同目标还在 `0x53FD78`、`0x53FE68`、`0x5431DC`、`0x543248` 的 ADRP+ADD 对出现。Release UI cave 的 `0xC6F0D8` 与 `0xC6F0F4` 两对也解码至 `0x28C19F8`。按 `0x50` 步长、`+0xC` 等级字段读取，7 个 floor 与 11 个 skip 共 18 项全匹配；将表地址试移 `-0x10`、`+0x10`、`-0x100`、`+0x100` 均为 0/18 匹配。这不等于证明整个关卡表所有字段跨版相同。

指令规则与本次实际证据应区分：

- 普通 B/BL 目标为 `PC + sign_extend(imm26) * 4`。只有源与目标同移，原指令的相对量才保持；本次已实证两组不同移位。
- ADRP 目标页为 `(PC & ~0xFFF) + sign_extend(imm21) * 0x1000`，ADD 再加目标低位。移动代码洞后，必须依据新 PC 和真实数据目标重新编码；不能把普通 B/BL 的“同移即可”规则直接用于非页对齐搬迁。
- STAGE_DB 不跟随后段代码减 `0x10`；字段偏移 `0xC`、对象偏移 `0x1BC4`、步长 `0x50` 都不是模块 VA，不能套代码位移。
- cave 中用 MOVZ/MOVK 装入的 LR 白名单及自身 `CAVE+4` 常量不是 PC 相对分支，搬迁 cave 不会自动更新这些常量。
